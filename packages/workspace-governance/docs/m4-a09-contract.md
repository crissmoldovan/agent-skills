# M4/A09 open, host action, and coordination contract

M4/A09 adds a non-live host boundary. `workspacectl open TARGET` resolves an exact persisted primary repository workspace or a group member map, verifies checkout identity, and returns the bounded A08 context without changing local state, checkout bytes, directories, host state, or process cwd.

`open TARGET --host hermes --activate` returns an inert typed action with its stable ID and semantic digest. It describes the native Hermes `desktop_project` sequence: list Projects, create one only when no persisted host binding exists, then switch to the exact Project. Product code never invokes that tool, edits Hermes internals, or treats shell `cd` as activation. `--host terminal --activate` returns only a launch target. Unsupported activation is bounded.

After the portable skill executes `desktop_project list`, `desktop_project create` when required, and `desktop_project switch`, it records an ordered result for every native request and obtains the effective tool cwd from a real tool running in that Project. Explicit activation CAS-persists a pending action receipt; `host acknowledge --action FILE --readback FILE --config CONFIG` loads current config/catalog/local-state revisions and consumes that receipt once by CAS. It accepts only the exact action ID/digest and ordered native result chain, binds a created Project ID from the create result through the final switch/readback, and requires the expected Project name/path and exact effective tool cwd. Wrong, stale, replayed, shell-cd-only, or mismatched readback returns `ACTION_FAILED`; no success is inferred from process cwd or an unverified claim.

A coordination workspace is a non-Git local binding with a stable ID, selected scope, member repository/workspace IDs, path, optional host Project ID, declared generated files, and revision. `coordination create` emits an approved `coordination-create` plan. Apply re-derives current members and checkout identities, checks exact revisions, opens the validated parent directory no-follow, and creates the directory and declared files through descriptor anchors with exclusive/no-follow flags and identity checks. It verifies generated bytes before CAS, CAS-writes local state, and reads both generated bytes and binding back. A post-CAS readback failure leaves only a fully verified binding+directory state; pre-CAS failures remove only identity-matched generated artifacts. Existing destinations, repository overlap, ancestor/component replacement, symlink redirection, wrong approval, stale inputs, and collisions refuse.

`coordination open --id ID` reopens by stable binding and rechecks the directory, binding revision, every repository/workspace selection, path, and remote. Missing, changed, ambiguous, or foreign members produce drift and exit 3 without mutation. No source tree is copied. No unregister command is exposed in A09, so no recursive deletion surface exists.

All native Hermes activation remains a live acceptance boundary outside package tests. Tests and the packed-installed route exercise only inert actions, acknowledgement validation, and isolated synthetic Git/non-Git fixtures.
