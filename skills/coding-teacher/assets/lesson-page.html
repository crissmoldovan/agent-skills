Lesson 1 of 4

What happens when you open a website?

New wordsbrowserserverrequest

The short answer

Opening a website is one computer asking another for a page. The one that answers is called a server.

A browser is the program a guest looks at websites with: Chrome, Safari, Edge. When they type the address, the browser sends a request, a message asking for a page, across the internet to a server: a computer that stays switched on, waiting for requests.

The server sends the page back, and the browser draws it on the screen. This happens on every click, usually in well under a second.

In kitchen terms

It’s the pass. An order goes in, a plate comes out. Where it stops matching: a server serves thousands of orders at once, in under a second, and forgets each guest as soon as it has answered them.

In our project

The booking site is the server’s answer. Its code is in the folder web/, and it runs on a hosting company’s servers, so nobody’s own computer needs to be on.

Lesson 2 of 4

What is a database?

New wordsdatabasetablerowcolumn

The short answer

A database is an organised store of information that a computer can search, sort and change in an instant.

The information is kept in tables, one for each kind of thing: bookings, tables, opening hours. Each row is one thing, such as one booking, and each column is one detail every row has, such as its time.

Because every booking has the same columns, the site can ask the database questions like “which tables are free at 19:30?” and get the answer at once, even with years of bookings in it.

In kitchen terms

The reservations book: a line per booking, the same details on every line. Where it stops matching: many people can write in it at the same moment without overwriting each other, and it answers a question about every line ever written in moments.

In our project

The bookings live in a table called bookings. Its columns are described in db/schema.sql, and the site reads and writes it from web/bookings.ts.

Lesson 3 of 4

What is a background job?

New wordsjobqueueworker

The short answer

A background job is work the site hands off to be done a moment later, so the guest doesn’t have to wait for it.

Some work is slow or can fail, like sending an email. Instead of making the guest wait, the site writes a job, a note of work to be done, and puts it in a queue, a waiting line of jobs.

A worker is a separate program that takes jobs from the queue one at a time and does them. If one fails, it can try again later without anyone noticing.

In kitchen terms

The ticket rail. Orders wait in turn, and a cook takes the next one when free. Where it stops matching: a failed job goes back on the rail by itself, and nobody has to be watching for the next one to start.

In our project

The worker’s code is in worker/. The confirmation email is the job send-confirmation, and it tries three times before it gives up.
