# Workspace Governance v0.1 specification

Read-only release candidate; unpublished. The normative S1–S9 contract below supersedes earlier drafts.

## S1 hierarchy/workspace (implementability B1)
Exactly one root, kind user OR organization; explicit visibility required on root. Legal parents: user:none, organization:user or none, area:organization|area, project:organization|area, repository:project, workspace:repository. No session nodes. Depth <=32. Workspace nodes stable catalog identities with optional policy but no portable absolute path. Inventory never creates node IDs or ancestry. 0.1 plans support org/area/project/repository scope and reject workspace scope with UNSUPPORTED; workspace policy is still resolvable by explicit node ID. Workspace checkout binding/execution deferred, documented as unbound; local worktrees observed separately. This avoids inventing binding identity from path. One authority snapshot may have user root only for personal ownership; organization-root recommended for sharing. Caller-supplied library defaults/invocation settings explicitly resolved before/after scope policies; no auto user config discovery and no organization roster embedded in base skill.

## S2 snapshot/authorization (security B2/B3, implementability B2/B5)
Manifest has NO revision; exact wire keys apiVersion, authorityId, nodes, policies, workflows, metadata. Envelope {manifest,revision,complete,stale,authorization,coverage,subject}: coverage MUST 'authority' in 0.1; complete MUST true; stale MUST false; authorization advisory|enforced; subject null for advisory or nonempty bound principal for enforced. Unknown/omitted completeness/freshness fails. File revision SHA256 exact captured UTF8 bytes; memory revision canonical manifest SHA256. Copy before validate/use; no nested mutation can change snapshot in place. Revision is opaque, not authentication. Enforced store must be constructed by trusted host with authenticated subject; resolver rejects different requested subject. Complete enforced authority may be delivered ONLY to trusted host core, never an untrusted client; external subject-filtered projection adapters are explicitly unsupported v0.1. Future scoped stores need explicit ancestry/dependency closure contract. All file/memory outputs advisory; CLI cannot switch to enforced by manifest claim. Global revision changes MAY reveal that authority changed; explicitly no hidden-change noninterference guarantee for advisory whole-authority snapshots. Local file freshness means current captured file, not upstream Git freshness. Adapter failure never fallback. Pure services accept validated envelope not file path. Ports can be async and remote implementations inject via library; no automatic code loading.

## S3 visibility (security B1, implementability B5)
Effective audience is intersection along ancestry. Omitted visibility inherits. public restriction contributes no filter; restricted requires nonempty readers array (private represented singleton principal). CLI catalog fixed projection id,kind,slug,parentId only. Opaque metadata NOT emitted. Known structural node references (parentId, nodeId) emitted only on fully readable ancestry; hidden node query generic UNAVAILABLE identical to absent. No typed arbitrary cross-project reference feature shipped; metadata treated as opaque author content, never interpreted. Policy and workflow text deliberately visible to readers of their scope; author responsible not to put secrets/hidden names into readable text. Do not claim string redaction prevents arbitrary leaks. Diagnostics generic codes, no raw parse input, stderr, hidden names or counts. validate and raw discover are operator-local administrative commands (not principal-filtered); callers already possess files/GitHub credentials. audit/plan only emit selected readable repository facts; no unmanaged remote names outside scope. If selected subtree contains unreadable descendants, refuse whole plan generically rather than silently omit obligations. Existing destination occupied by other repo reports target and blocked code only, no other repo identity. Snapshot-wide opaque revision exposure explicitly allowed as above.

## S4 exact schema and merge algebra (implementability B3)
Policy {nodeId,settings:[],constraints:[]}, at most one per node. Workflow {nodeId,id,steps:[],settings:[],constraints:[]} unique nodeId+id. Node optional metadata defaults {}; top metadata defaults {}; Require nodes/policies/workflows/metadata top arrays/object explicitly for one strict schema. Node required id,kind,slug,parentId; optional remote only repository, metadata,visibility. Constraints globally unique source-qualified identities (nodeId, workflowId-or-policy, id); duplicate IDs within source reject, same ID in another source adds constraint not replacement.
Setting remove record {key,merge:'remove'} has NO value. Other settings {key,merge:replace|deep-merge|append|set-union|keyed-merge,value:JSON}. key dot-separated nonempty safe segments, rejects __proto__,prototype,constructor. Dotted keys are flat logical fields (git.x), not paths into arbitrary nested maps. No prefix overlap keys e.g. a and a.b anywhere participating (reject) to avoid locks bypass. All setting keys and nested JSON reject prototype keys, nonfinite numbers, depth >32, excessive entries; file max 2MiB, nodes <=10000, records <=20000, strings <=16384. Reject duplicate JSON object keys using strict parser; do not silently last-win.
replace: any bounded JSON including null; absent creates. deep-merge: value object, absent starts {}, recursively object+object; same-type scalar leaf replaces; arrays replace as leaves; null only compatible with null (type conflict otherwise). append/set-union: array only; absent starts []; existing nonarray fails; append concatenates; union canonical JSON equality preserves first appearance, no sorting emitted values. keyed-merge: array of objects each id nonempty unique, nested content JSON; absent starts []; matching ID recursive deep merge, new append; order retained. Whole-setting remove requires existing key or errors. Type mismatches error. Workflow steps use separate keyed operation: present {id,action,inputs} FULL replacement at same position (not fuzzy recursive inheritance); new append; tombstone {id,remove:true} only, missing id error; remove then later readd appends. Duplicate IDs in one layer reject. constraints {id,key,operator:equals|forbidden-values|required-members,value}; equals missing FAIL; forbidden-values operand array and missing PASS; required-members operand array, final value array, missing FAIL. Constraint violations error after final resolution; all inherited constraints retained and evaluate final settings including defaults/invocation/workflow. No bypass. Unselected workflows contribute nothing.
Canonical JSON sorts object keys by lexical codepoint, arrays keep order, finite numbers JS JSON encoding (-0=0), UTF8. Provenance records each field-level operation {nodeId,workflowId|null,key,merge,value?}, snapshot revision at resolution envelope. Defaults/invocation synthetic source labels, no real node IDs. Removed field provenance retained, constraint sources retained. Nested deep-map values trace to same field operation (no invented per-leaf tracing promise).

## S5 workflow CLI (implementability B4)
Only chosen --workflow ID resolves; absent definition -> UNAVAILABLE. Per scope chosen workflow settings then ordinary policy settings; workflow and ordinary constraints accumulated. steps named stable IDs rules S4. Output is 'resolved workflow definition', executable:false. --workflow supported explain, workflow, plan, audit, verify-plan. Library options defaults/invocation only; CLI override editing deferred to avoid arbitrary JSON flags. verify-plan uses same explicitly supplied workflow, node, principal, root (never trust values in plan to select resources). Arbitrary action strings inert; no shell/prompt execution anywhere.

## S6 remote canonicalization (security B6, implementability B6)
Supported input exact patterns: https://github.com/OWNER/REPO optionally .git suffix and one trailing /; git@github.com:OWNER/REPO optionally .git, ssh://git@github.com/OWNER/REPO optionally .git. No port, password, query, fragment, percent escape, Unicode, extra slash, whitespace, local path, file:// or ext::. Owner ASCII alnum with interior single hyphens max39; repo ASCII alnum underscore dot hyphen max100, cannot . or .., no trailing dot except optional .git suffix stripping. Canonical lowercase HTTPS without suffix/trailing slash. Validate raw pattern BEFORE normalization. Manifest remote accepts ONLY canonical HTTPS exact string (so malformed literal never silently repaired); observations canonicalize supported forms. Host numeric IDs informational only, no rename reconciliation/reused-path identity guarantee.

## S7 Git read-only and metadata containment (security B4/B5, implementability B7)
Require explicit existing real root, no symlink root/ancestors. Walk only regular dirs within root, no symlink traversal. Every .git pointer and commondir resolved before Git invocation; metadata realpaths must remain in scan root and no symlink components. External metadata -> incomplete scan error without printing target. Support linked worktrees only if checkout, common repo metadata all inside root. Reject symlinked .git or commondir. No git worktree list output required (avoid other path leakage); worktree bool from .git file. Scan nested directories inside checkouts excluding .git,node_modules,dist,coverage,etc to discover nested repos conservatively.
Run fixed execFile git commands only. Env removes all GIT_* inherited variables; set GIT_CONFIG_NOSYSTEM=1, GIT_CONFIG_GLOBAL to OS null device, GIT_OPTIONAL_LOCKS=0, GIT_TERMINAL_PROMPT=0, GIT_PAGER=cat. Rebind GIT_WORK_TREE to the inspected checkout after stripping inherited variables; local core.worktree must not redirect status. git -c core.fsmonitor=false -c core.untrackedCache=false -c core.hooksPath=<OS-null> -c maintenance.auto=false -c gc.auto=0 -c core.excludesFile=<OS-null>. Commands config --local --no-includes --get remote.origin.url; rev-parse --verify HEAD (unborn gets null); status --porcelain=v1 --untracked-files=all --ignore-submodules=all (submodule traversal unsupported, scanning handles nested repos independently). Bound output 2MiB, timeout30s. Index bytes must unchanged; fsmonitor and clean/process sentinels must not execute. Before status, run config --includes --null --name-only --list under the same sanitized environment and fixed overrides. Reject any effective filter.<name>.clean or filter.<name>.process key (even empty or unused), including ordinary/conditional includes and enabled worktree config, as generic GIT_METADATA_OR_STATUS incomplete without invoking status. This preserves dirty semantics rather than disabling filters and claiming a complete scan. Config reads remain possible; parse, output-limit or timeout failures also fail closed generically. Root restriction is best-effort traversal, not OS sandbox against concurrent attacker; no automatic mutations. Fixed executable resolution assumes trusted PATH.

## S8 inventory and deterministic plans (security B7, implementability B6/CLI)
Inventory {root:absolute real path,complete:boolean,errors:[{code}],repositories:[{path:absolute,remote:string|null,head:string|null,dirty:boolean,worktree:boolean,status:string}],occupiedPaths:[absolute paths],unsafePaths:[absolute non-directory paths, including regular files and symlinks]}. status is internal bounded porcelain, scoped plans never expose filenames. Depth default8, max32, entries max50000; reaching depth with unexamined child dirs marks incomplete (including directories in checkouts); skipped dependency/metadata dirs documented outside coverage. Empty root complete. Occupied paths include files+directories so wrong target detected. Root paths captured but not public fixtures. git/status failures -> complete:false; no remote -> remote:null + incomplete (cannot establish identity). Unknown branch HEAD only valid unborn, other error incomplete.
Plan/audit internally discoverLocal --root [--depth], no remote calls. GitHub inventory is separate administrative connector output for manual catalog adoption; not used as authoritative clone/delete catalog input. Owner validation before fixed gh api --hostname github.com /orgs/OWNER/repos?per_page=100&page=N&type=all; stop on page length<100, bounded pages100 and timeout, malformed/repeated pages/error reject rather than partial success. gh env must not honor GH_HOST override for target; raw stderr not returned.
Plan has apiVersion:'workspace-governance/plan-v1', executable:false, authorityId,revision,nodeId,principal,authorization,root,workflowId:null|string,policyFingerprint,inventoryDigest,entries. Each entry {repositoryId,remote,target,status,presentPaths,dirty}; statuses present|missing-checkout|misplaced|duplicate|blocked. Dirty at desired path -> blocked; multiple matched clones -> duplicate even dirty (dirty bool retained). Destination exists but not same matched repo -> blocked. Any unsafe ancestor or case-fold path collision -> blocked. No selected readable repos -> entries empty success; invisible descendant plan -> UNAVAILABLE. Partial inventory fails INCOMPLETE exit3 no plan printed. Audit emits same preview plus drift boolean, exits3 if any non-present; plan emits preview exits0 even drift (preview valid). verify-plan recomputes exact canonical plan using explicit arguments; compares entire canonical plan, including all fields; extra/missing fields fail STALE_PLAN exit3. Does not echo parsed plan. Plan parser same bounded strict JSON. No approval authenticity implied.
Digest excludes timestamps and observation order; sorts repos/occupied/unsafe/errors, includes root/complete/status/head/dirty/worktree/remote/path. Files content changes while status unchanged are NOT detected; document observation-level preview freshness only. Whole inventory digest is allowed local administrative change signal but doesn't include raw unrelated paths in plan. Fingerprint reflects selected resolutions/options. Repeated unchanged preview verifies. Changes in settings, selected workflow, principal, root, target, HEAD/status, or steps reject. Fresh observation TOCTOU remains; future apply must not use this as authorization.

## S9 distribution and tests
CLI JSON only, no --human flag. Error {error:{code,message}} stderr with static bounded message. Exit0 success,2 invalid/unavailable/unsupported/tool failure,3 incomplete/drift/stale (highest priority invalid2 when no valid input). --help text and --version permitted. Unknown flags reject including unsupported mutations. No package lifecycle install scripts, private:true, dist JS/declarations exports, schemas/examples/README/LICENSE packaged. Skill install carries all relative references; CLI installed separately from built local tarball, no published registry claim. Linux Node24+ is verified environment; POSIX macOS code paths expected but not tested; Windows support not claimed until platform subprocess/path matrix tested. Live GitHub smoke only explicit synthetic/public owner or user-requested org and credential, not mandatory CI. Private result artifacts outside repository. Root npm verification invokes new package explicitly. Test contract should validate schema against same representative good/bad manifests used by runtime to prevent documentation drift.
